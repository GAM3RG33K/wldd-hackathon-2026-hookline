# 2026-10-16 — Project Phoenix v2: local retention model + Next.js web app

- Goal: rebuild the product on the `project-v2` branch — retention model runs locally on Apple Silicon, new web frontend per the approved design PDFs, backend APIs replicated, no legacy naming anywhere user-facing.

## What was built

- `project-v2` branch (from `main` @ 6a27a3b). No videos/weights/preds/samples committed (`samples_v2/` gitignored).
- **Scoring** `phoenix/scorer.py`: report from a retention curve R(1..60) — hook/hold/finish, hooks (consecutive climbs), drop-off zones (consecutive drops), attention (within-video normalised, avg ≈ 50), weighted virality breakdown, timestamped suggestions ranked by viewers lost. Method string unchanged: `heuristic, within-video normalised, uncalibrated`.
- **Model access** `phoenix/ttcc.py`: subprocess call into the pinned model env (MPS, bf16) → `r_pred.json` + provenance. `phoenix/patch_ttcc_env.py` fixes the env durably (transformers version-check skip; PyAV `metadata_errors` call-sites; broken huggingface_hub dist-info reinstalled 0.36.2).
- **Backend** `backend/app.py`: `POST /api/analyze` (background job thread, model-load lock), `GET /api/report/{id}` (live status + report), `GET /api/reports`, `GET /api/media/{id}` (streams the video even before the report lands), `GET /health` (incl. model-env status). Demo fallback curve marked `demo: true` when the model env or free memory is insufficient.
- **Honest progress**: backend publishes `status.json` per step (progress %, stage index, product-worded detail — "Reading your video…", "Analysing your reel second by second…", "Scoring the watch-through…"); web app renders exactly what the backend publishes. Verified: no jargon (model/TTCC/MPS/GPU) in any user-facing string.
- **Web app** `wlddhq-v2/` (Next.js 16, app router): design system from the PDFs (peach canvas, 2px ink borders, hard offset shadows, blue/lime/yellow). Pages: upload (default reel = shortest sample FL005 7.7s + prefitted caption), processing (8 stage rows + progress bar driven by backend), report (realtime video player with timecode burn-in + transport, per-frame chart sync via rAF, drag-chart-to-scrub, chart layers Retention/Zones/Cuts/Emotion, why-viral switches + "How the score is calculated", editing suggestions, emotions/caption/transcript cards with honest demo marking, export modal PDF/JSON/MD), `/reports` list.
- Launchers: `setup.sh` (venv `.venv-v2` + import verification), `run_dev.sh` (backend :8000 + web :3000, health-check gate). v1 launcher renamed `run-demo.sh` → `old-run-demo.sh`; new `launch-services.sh` for the v1 TUI path.
